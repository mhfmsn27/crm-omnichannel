Dokumen teknis lengkap untuk men-deploy CloudChat Omnichannel AI System pada server VPS/Dedicated Ubuntu 24.04 LTS. Mencakup seluruh tahapan — dari persiapan server, instalasi basis data PostgreSQL dengan PGVector, konfigurasi backend dan frontend, hingga deployment NGINX dengan SSL.

1 Prasyarat Infrastruktur Minimum Requirements

Sebelum memulai proses deployment, pastikan spesifikasi server VPS atau Dedicated Anda memenuhi standar berikut. Mengabaikan persyaratan ini dapat menyebabkan performa tidak optimal atau kegagalan instalasi.

Komponen Minimum Direkomendasikan Keterangan
vCPU 2 Core 4 Core Pemrosesan AI (embedding) membutuhkan CPU yang memadai
RAM 4 GB 8 GB 8GB direkomendasikan untuk pemrosesan AI yang optimal
Sistem Operasi Ubuntu 24.04 LTS (Murni) Tanpa panel kontrol pihak ketiga seperti cPanel atau Plesk
Domain Domain aktif dengan A Record A Record harus sudah diarahkan ke IP publik VPS. Nonaktifkan Cloudflare Proxy pada tahap awal
Akses SSH Root / Sudo Diperlukan untuk instalasi paket sistem dan konfigurasi firewall
Storage 20 GB 50 GB+ Tergantung volume media yang diunggah pengguna
⚠️
Perhatian: Cloudflare Proxy
Pada tahap awal instalasi, nonaktifkan Cloudflare Proxy (ubah ikon awan jadi abu-abu / DNS Only) di dashboard Cloudflare Anda. Certbot membutuhkan akses langsung ke server untuk validasi sertifikat SSL. Proxy dapat diaktifkan kembali setelah SSL berhasil dipasang.

2 Persiapan Lingkungan Server & Dependencies

Lakukan pembaruan repositori sistem dan instalasi seluruh paket esensial yang dibutuhkan CloudChat. Jalankan perintah berikut secara berurutan melalui terminal SSH sebagai root atau pengguna dengan akses sudo.

🔄 Update Sistem & Instalasi Paket Dasar

Bash
# Update sistem dan instalasi dependensi dasar
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx curl git build-essential unzip redis-server ufw

🔥 Konfigurasi Firewall (UFW)

UFW (Uncomplicated Firewall) digunakan untuk membatasi akses ke server. Kita hanya membuka port yang diperlukan: SSH (koneksi remote) dan Nginx Full (HTTP + HTTPS).

Bash — Firewall UFW
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw --force enable

🟢 Instalasi Node.js 20 LTS

CloudChat menggunakan Node.js sebagai runtime backend dan frontend. Versi 20 LTS adalah versi stabil yang didukung secara penuh.

Bash — Node.js & PM2
# Instalasi Node.js (Versi 20 LTS) dari repositori resmi NodeSource
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# Instalasi PM2 — Process Manager untuk Node.js (menjaga app tetap berjalan)
sudo npm install -g pm2

# Aktivasi Service Redis (digunakan untuk caching dan queue)
sudo systemctl enable redis-server
sudo systemctl start redis-server
ℹ️
Tentang PM2
PM2 adalah process manager untuk Node.js yang memastikan aplikasi backend tetap berjalan bahkan setelah server reboot. PM2 juga menyediakan log management, monitoring, dan kemampuan zero-downtime reload.

3 Instalasi PostgreSQL & Ekstensi PGVector

CloudChat membutuhkan PostgreSQL 16 dengan ekstensi pgvector untuk mendukung fungsionalitas memori AI berbasis Vector Embeddings. PGVector memungkinkan pencarian semantik dan penyimpanan representasi vektor dari percakapan.

📥 Instalasi PostgreSQL 16

Bash — PostgreSQL
# Tambahkan repositori resmi PostgreSQL
sudo sh -c 'echo "deb https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'

# Import GPG Key untuk verifikasi paket
wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo apt-key add -
sudo apt update

# Instalasi PostgreSQL 16 beserta ekstensi PGVector
sudo apt install postgresql-16 postgresql-16-pgvector -y

# Aktifkan dan jalankan service database
sudo systemctl start postgresql
sudo systemctl enable postgresql

🗄️ Konfigurasi Kredensial Basis Data

Masuk ke konsol PostgreSQL sebagai superuser postgres untuk membuat user dan database khusus CloudChat:

Bash — Masuk ke Konsol PostgreSQL
sudo -u postgres psql

Setelah prompt PostgreSQL terbuka (postgres=#), eksekusi perintah SQL berikut satu per satu:

SQL — Setup Database & Ekstensi
-- Buat User & Database untuk CloudChat
CREATE USER omni_user WITH PASSWORD 'DefaultPassword123!';
CREATE DATABASE omni_db;
ALTER USER omni_user WITH SUPERUSER;
GRANT ALL PRIVILEGES ON DATABASE omni_db TO omni_user;

-- Hubungkan ke database dan pasang ekstensi yang dibutuhkan
\c omni_db
GRANT ALL ON SCHEMA public TO omni_user;
ALTER SCHEMA public OWNER TO omni_user;

-- Pasang ekstensi PGVector (untuk memori AI) dan UUID
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- Keluar dari konsol PostgreSQL
\q
💡
Ganti Password Database di Produksi
Nilai DefaultPassword123! di atas hanya untuk referensi. Wajib ganti dengan password yang kuat dan unik sebelum deployment ke produksi. Pastikan password yang sama Anda masukkan ke file .env backend di langkah 5.

7 Deployment Backend & NGINX

▶️ Menjalankan Backend dengan PM2

PM2 akan menjalankan proses backend Node.js dan memastikannya otomatis restart jika server reboot atau terjadi crash.

Bash — PM2 Start
cd /var/www/omnichannel/backend

# Jalankan backend dengan nama proses "omni-backend"
pm2 start server.js --name "omni-backend"

# Simpan daftar proses PM2
pm2 save

# Generate perintah startup — SALIN dan JALANKAN output perintah ini
pm2 startup
⚠️
Setelah menjalankan "pm2 startup"
Perintah pm2 startup akan mencetak sebuah perintah sudo env PATH=... di terminal. Salin dan jalankan perintah tersebut agar PM2 benar-benar aktif otomatis saat server reboot. Jika tidak, backend tidak akan berjalan setelah VPS direstart.
💡
Perintah PM2 yang Berguna
pm2 status — Lihat status semua proses  |  pm2 logs omni-backend — Lihat log real-time  |  pm2 restart omni-backend — Restart proses  |  pm2 reload omni-backend — Reload tanpa downtime  |  pm2 stop omni-backend — Hentikan proses

🌐 Konfigurasi Reverse Proxy NGINX

NGINX bertindak sebagai reverse proxy — menerima request dari internet dan meneruskannya ke proses Node.js yang berjalan di port 8998. NGINX juga yang akan menangani SSL/HTTPS.

Bash — Buat Konfigurasi NGINX
sudo nano /etc/nginx/sites-available/omnichannel

Salin dan tempel konfigurasi berikut ke dalam editor. Ganti semua kemunculan your-domain.com dengan domain Anda yang sebenarnya:

NGINX — Konfigurasi Virtual Host
server {
    listen 80;
    server_name your-domain.com;

    # Batasi ukuran upload file — sesuaikan dengan limit multer di backend (50MB)
    client_max_body_size 50M;

    location / {
        # Teruskan semua request ke Node.js di port 8998
        proxy_pass         http://localhost:8998;
        proxy_http_version 1.1;

        # Header untuk WebSocket (dibutuhkan untuk real-time chat)
        proxy_set_header   Upgrade      $http_upgrade;
        proxy_set_header   Connection   "upgrade";
        proxy_set_header   Host         $host;
        proxy_cache_bypass $http_upgrade;

        # Header untuk meneruskan IP asli pengguna
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}

✅ Aktivasi NGINX & Instalasi SSL

Bash — Aktivasi & SSL
# Aktifkan konfigurasi dengan membuat symlink
sudo ln -s /etc/nginx/sites-available/omnichannel /etc/nginx/sites-enabled/

# Hapus konfigurasi default NGINX
sudo rm /etc/nginx/sites-enabled/default

# Test konfigurasi NGINX (pastikan tidak ada error sintaks)
sudo nginx -t

# Restart NGINX untuk menerapkan konfigurasi
sudo systemctl restart nginx

# Instalasi Certbot untuk sertifikat SSL gratis dari Let's Encrypt
sudo apt install certbot python3-certbot-nginx -y

# Pasang sertifikat SSL — ganti dengan domain Anda
sudo certbot --nginx -d your-domain.com
✅
Certbot Otomatis Memperbarui Konfigurasi NGINX
Setelah Certbot berhasil, ia akan otomatis memodifikasi konfigurasi NGINX Anda untuk menggunakan HTTPS (port 443) dan menambahkan redirect dari HTTP ke HTTPS. Sertifikat SSL dari Let's Encrypt berlaku 90 hari dan akan diperbarui otomatis oleh Certbot.

! Troubleshooting & Problem Umum

Daftar error paling sering muncul saat instalasi. Gunakan pencarian browser (Ctrl+F) untuk menemukan solusi spesifik.

1. npm install EACCES / permission denied

⚠️
Gejala: Terminal menampilkan EACCES permission denied saat npm install.
Bash — Perbaikan Hak Akses
# Pastikan folder dimiliki user aktif
sudo chown -R $USER:$USER /var/www/omnichannel

# Hapus lock + install ulang
rm -rf node_modules package-lock.json
npm install

# Jika error saat npm global (PM2)
sudo npm install -g pm2

2. PostgreSQL password authentication failed

⚠️
Gejala: password authentication failed for user "omni_user" di PM2 logs.
Bash — pg_hba.conf
# Edit pg_hba.conf
sudo nano /etc/postgresql/16/main/pg_hba.conf

# Pastikan method autentikasi scram-sha-256 atau md5:
local   all     all                             scram-sha-256
