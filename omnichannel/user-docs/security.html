🛡️ Keamanan Platform

Panduan lengkap untuk mengamankan platform CRMHUB, melindungi data pelanggan, dan mencegah akses tidak sah.

🔒
Keamanan adalah Tanggung Jawab Bersama

Sebagai pengelola instance CRMHUB, Anda bertanggung jawab atas keamanan server, data pelanggan, dan akun pengguna. Ikuti semua panduan berikut untuk perlindungan maksimal.

Checklist Keamanan Wajib

Praktik KeamananPrioritasDeskripsi
Gunakan SSL/HTTPSWajibSemua lalu lintas data harus dienkripsi dengan SSL. Pasang sertifikat SSL valid (Let's Encrypt gratis) dan redirect semua HTTP ke HTTPS.
Aktifkan Firewall ServerWajibKonfigurasi UFW atau iptables. Buka hanya port 80, 443, dan 22 (SSH). Blokir semua port lainnya dari akses publik.
Backup Database HarianWajibJadwalkan pg_dump otomatis setiap hari. Simpan backup di lokasi terpisah (cloud storage, S3, atau server lain). Test restore berkala.
Ganti Password DefaultWajibSegera ganti password superadmin@example.com setelah instalasi pertama. Gunakan password minimal 16 karakter.
Batasi Akses SSHPentingGunakan SSH key authentication, nonaktifkan password login SSH. Pertimbangkan mengubah port SSH dari 22 ke nomor non-standar.
Update Dependensi RutinPentingJalankan npm audit dan update library secara berkala. Pantau CVE untuk Node.js dan PostgreSQL.
Proteksi .env FilePentingPastikan file .env tidak bisa diakses via web (location ~ /\.env { deny all; } di Nginx). Jangan commit ke version control.
Penggunaan JWT Secret KuatPentingGanti JWT_SECRET di .env dengan string acak minimal 64 karakter. Jangan gunakan nilai default.
Rate Limiting APIDisarankanKonfigurasikan rate limiting di Nginx untuk mencegah brute force dan serangan DDoS pada endpoint API.
Monitoring LogDisarankanPantau log akses Nginx dan log aplikasi Node.js secara berkala. Gunakan tools seperti Fail2Ban untuk blokir IP mencurigakan.

Kebijakan Password

Terapkan kebijakan password yang kuat untuk semua pengguna CRMHUB:

🔢

Panjang Minimal

Gunakan minimal 12 karakter. Semakin panjang semakin baik.

🔀

Kombinasi Karakter

Gabungkan huruf besar, huruf kecil, angka, dan simbol (!@#$%).

🔄

Ganti Berkala

Ganti password akun admin setiap 90 hari sebagai praktik terbaik.

❌

Jangan Pakai Ulang

Gunakan password unik untuk CRMHUB, jangan sama dengan platform lain.

Keamanan Akses Pengguna

Prinsip Least Privilege

Berikan setiap anggota tim hanya izin yang mereka benar-benar butuhkan:

  • Agent/Staff — hanya akses Inbox dan fitur yang diperlukan sehari-hari
  • Supervisor — tambah akses laporan dan manajemen agent dalam divisinya
  • Admin — akses penuh ke pengaturan, tapi bukan Super Admin
  • Super Admin — hanya untuk pengelola platform, jangan dibagikan ke tim operasional

Audit Akses Berkala

Lakukan audit daftar pengguna minimal setiap 3 bulan:

  1. Buka Settings → Manajemen Tim.
  2. Review daftar anggota aktif. Hapus atau nonaktifkan akun karyawan yang sudah tidak bekerja.
  3. Periksa apakah role setiap anggota masih sesuai dengan tanggung jawabnya.
  4. Ganti role ke level lebih rendah jika ada yang memiliki akses berlebihan.
⚠️
Segera Nonaktifkan Akun Karyawan yang Keluar

Saat ada karyawan yang berhenti, segera hapus atau nonaktifkan akun mereka di CRMHUB dan cabut akses perangkat WhatsApp yang ditugaskan. Jangan menunggu.

Keamanan API Key

API Key digunakan untuk integrasi eksternal dan otomasi. Lindungi API Key Anda:

  • Jangan hardcode API Key langsung di kode aplikasi — gunakan environment variable
  • Jangan share API Key melalui chat atau email yang tidak terenkripsi
  • Regenerate (buat ulang) API Key jika dicurigai bocor — langsung dari menu Developer → API Keys
  • Gunakan API Key berbeda untuk setiap aplikasi/integrasi agar mudah dicabut jika diperlukan
  • Terapkan IP whitelist pada penggunaan API Key jika memungkinkan

Perlindungan Data Pelanggan

Data pelanggan yang tersimpan di CRMHUB bersifat sensitif dan harus dijaga kerahasiaannya:

Langkah PerlindunganImplementasi
Enkripsi di TransitHTTPS/TLS wajib aktif untuk semua komunikasi antara browser dan server
Enkripsi di PenyimpananAktifkan enkripsi disk pada VPS/server (LUKS untuk Linux)
Retensi DataTetapkan kebijakan berapa lama data disimpan. Hapus data yang sudah melebihi batas retensi
Akses DatabaseDatabase PostgreSQL tidak boleh terbuka ke publik. Hanya bisa diakses dari localhost atau IP server tertentu
Anonimisasi LaporanSaat membagikan data laporan, hapus atau samarkan data identitas pribadi yang tidak diperlukan

Strategi Backup

Kehilangan data bisa terjadi akibat kesalahan manusia, hardware failure, atau serangan. Selalu punya backup:

Backup Otomatis Database

Contoh script cron untuk backup PostgreSQL harian:

# Tambahkan di crontab: crontab -e
0 2 * * * pg_dump -U postgres nama_database | gzip > /backup/crmhub_$(date +\%Y\%m\%d).sql.gz

# Hapus backup lebih dari 30 hari
0 3 * * * find /backup/ -name "crmhub_*.sql.gz" -mtime +30 -delete

Yang Harus Di-backup

  • Database PostgreSQL (semua tabel)
  • Folder /uploads (file yang diunggah pengguna)
  • File konfigurasi .env (simpan terenkripsi)
  • Konfigurasi Nginx/server

Respons Insiden Keamanan

Jika Anda mencurigai adanya pelanggaran keamanan:

  1. Isolasi segera — Jika ada akses tidak sah yang terdeteksi, nonaktifkan akun yang terlibat dan cabut semua token/API key aktif.
  2. Identifikasi sumber — Periksa log akses Nginx dan log aplikasi untuk mengetahui dari mana serangan berasal dan apa yang diakses.
  3. Ganti semua kredensial — Ganti JWT_SECRET, password database, password semua admin, dan regenerate semua API Key.
  4. Assess dampak — Identifikasi data apa yang mungkin terekspos. Beri tahu pengguna yang terdampak jika diperlukan.
  5. Perbaiki celah — Terapkan patch dan konfigurasi ulang sistem untuk menutup celah yang dieksploitasi.
  6. Dokumentasikan — Catat kronologi insiden, dampak, dan langkah perbaikan yang diambil.
ℹ️
Laporkan ke Support

Jika Anda menemukan kerentanan keamanan di platform CRMHUB, laporkan segera ke tim pengembang. Jangan publikasikan celah keamanan sebelum diperbaiki.

Enkripsi Database AES-256-GCM

Cryptographic Logic Binding

Engine pengiriman pesan WhatsApp memvalidasi token operasi derivatif (deriveOperationKey) secara internal.
